mkbrr includes a graphical user interface built with [Wails](https://wails.io/) for users who prefer a visual experience over the command line.

## Features

The GUI provides the same core functionality as the CLI with additional usability enhancements:

<CardGroup cols={2}>
  <Card title="Create" icon="plus">

  </Card>
  <Card title="Inspect" icon="magnifying-glass">
    View torrent metadata with a searchable, collapsible file tree.
  </Card>
  <Card title="Check" icon="circle-check">
    Verify torrent data with real-time progress. The results show the good pieces, the bad pieces, and the missing files.
  </Card>
  <Card title="Modify" icon="pen">
    Edit torrent metadata without needing the original source files.
  </Card>
</CardGroup>

### Create settings

The Create page has a control for each create setting of the CLI. The controls in this table are in the Advanced Options section:

| Control | CLI flag | What it does |
|---------|----------|--------------|
| Web Seeds | `--web-seed` | Adds web seed URLs, one URL per input. |
| Piece Length | `--piece-length` | Sets the piece length. |
| Max Piece Length | `--max-piece-length` | Sets the largest piece length that mkbrr can select. |
| Target Piece Count | `--target-piece-count` | Sets the approximate number of pieces. mkbrr selects the piece length from it. You cannot set it together with a piece length. |
| Exclude Patterns | `--exclude` | Leaves out the files that match the patterns. |
| Include Patterns | `--include` | Adds only the files that match the patterns. |
| Skip filename prefix | `--skip-prefix` | Does not add the tracker domain to the start of the output filename. |

Write the patterns as a comma-separated list, for example `*.nfo,*.jpg`. If you select a preset, the patterns of the preset also apply. See the [filtering guide](/features/filtering) for the pattern rules.

Tracker rules still apply. If the first tracker has a maximum piece length, the piece length lists show no larger sizes. A target piece count also cannot select a larger piece length.

You set the worker count on the Settings page, not on the Create page.

### Settings

The Settings page allows you to:
- Configure default worker count for hashing operations
- Manage presets (create, edit, delete)
- View and reload the preset file location

## Additional Features

<AccordionGroup>
  <Accordion title="Theme Support">
    Choose between light, dark, or system appearance modes, plus five color themes: Default, Autobrr (the default), Nightwalker, Swizzin, and Amethyst Haze.
  </Accordion>

  <Accordion title="Drag and Drop">
    Drag a file or folder onto the Create, Check, Inspect, or Modify page to fill in its path. On Create, drop the content. On Check, drop a `.torrent` file or the content. On Inspect and Modify, drop a `.torrent` file.
  </Accordion>

  <Accordion title="Create Plan">
    The Create page shows the create plan under the form. The create plan is what create will do, worked out before mkbrr hashes the files. It shows the content size after the exclude and include patterns, the piece length, the notices, and the season pack check. The GUI makes a new plan after each change to the form.

    If the plan fails, for example because the path does not exist, the error shows on one line under the plan. If the first tracker has tracker rules, the plan also shows its default source, its maximum piece length, and its maximum .torrent size. The rules of the other trackers do not apply, because create applies only the rules of the first tracker.
  </Accordion>

  <Accordion title="Form Persistence">
    Form state is automatically saved across sessions. If you close the app while filling out a form, your inputs will be restored when you return.
  </Accordion>

  <Accordion title="Preset Management">
    Full preset management with validation. Create, edit, and delete presets directly from the GUI without manually editing YAML files.
  </Accordion>

  <Accordion title="File Tree Viewer">
    The Inspect page features an advanced file tree viewer with:
    - Search functionality with auto-expand
    - Collapsible folder structure
    - File count per folder
    - All folders open at the start when the torrent has 50 files or fewer
  </Accordion>
</AccordionGroup>

## Open a torrent from the command line

To open a `.torrent` file on the Inspect page, run `mkbrr-gui` with the `inspect` command and the path to the file:

```bash
mkbrr-gui inspect /path/to/file.torrent
```

The GUI resolves a relative path against the folder where you run the command. If the file does not exist or is not a valid torrent, the Inspect page shows the error. If you run `mkbrr-gui inspect` with no path, the GUI opens on the Inspect page.

If a GUI window is already open, no second window opens. The open window comes to the front and shows the new torrent on the Inspect page.

<Note>
On macOS, use an absolute path when a GUI window is already open. On macOS, the open window resolves a relative path against the folder of the app, not against the folder where you run the command.
</Note>

### Windows context menu

You can add an "Inspect with mkbrr" entry to the right-click menu of `.torrent` files. The entry runs this command, where `%1` is the path of the file that you clicked:

```text
"C:\path\to\mkbrr-gui.exe" inspect "%1"
```

To add the entry, save this text as a `.reg` file. Change `C:\\path\\to\\mkbrr-gui.exe` to the location of your `mkbrr-gui.exe`, and keep the double backslashes. Then double-click the file to import it.

```reg
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.torrent\shell\mkbrr-inspect]
@="Inspect with mkbrr"

[HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.torrent\shell\mkbrr-inspect\command]
@="\"C:\\path\\to\\mkbrr-gui.exe\" inspect \"%1\""
```

## Installation

Download the GUI binary for your platform from the [GitHub Releases page](https://github.com/autobrr/mkbrr/releases).

The GUI is a separate binary, `mkbrr-gui`. If you already have the `mkbrr` CLI, keep it. You can install both on the same system.

<Tabs>
  <Tab title="macOS">
    Download `mkbrr-gui_*_darwin_*.zip` and extract the `.app` bundle.

    <Warning>
      The app is not notarized, so macOS will block it by default. Use one of these methods:
    </Warning>

    **Option 1: Remove quarantine attribute (recommended)**
    ```bash
    xattr -cr /path/to/mkbrr-gui.app
    ```

    **Option 2: Right-click to open**
    1. Right-click (or Control-click) on the app
    2. Select "Open" from the context menu
    3. Click "Open" in the dialog

    **Option 3: System Settings**
    1. Try to open the app (it will be blocked)
    2. Open System Settings > Privacy & Security
    3. Click "Open Anyway" next to the mkbrr-gui message
  </Tab>
  <Tab title="Windows">
    Download `mkbrr-gui_*_windows_amd64.zip` and extract `mkbrr-gui.exe`.

    Run the executable directly - no installation required.
  </Tab>
  <Tab title="Linux">
    The GUI needs WebKitGTK 4.1 (`libwebkit2gtk-4.1`) and GTK 3. Install them before you start the GUI:

    <CodeGroup>
    ```bash Debian/Ubuntu
    sudo apt install libwebkit2gtk-4.1-0 libgtk-3-0
    ```
    ```bash Fedora
    sudo dnf install webkit2gtk4.1 gtk3
    ```
    ```bash Arch
    sudo pacman -S webkit2gtk-4.1 gtk3
    ```
    </CodeGroup>

    Download `mkbrr-gui_*_linux_amd64.tar.gz` and extract the binary.

    ```bash
    tar -xzf mkbrr-gui_*_linux_amd64.tar.gz
    chmod +x mkbrr-gui
    ./mkbrr-gui
    ```
  </Tab>
</Tabs>

### Building from Source

If you prefer to build the GUI yourself:

```bash
# Clone the repository
git clone https://github.com/autobrr/mkbrr.git
cd mkbrr

# Install Wails CLI (one-time requirement)
make install-wails

# Build GUI for your current platform
make gui-build

# Or build for all platforms
make gui-build-all
```

The built application will be in `gui/build/bin/`.

<Note>
On Linux, `make gui-build` builds against WebKitGTK 4.0. If your system has only WebKitGTK 4.1, as Ubuntu 24.04 and later do, run `cd gui && wails build -tags webkit2_41` instead. The release builds use this tag.
</Note>

## GUI vs CLI

Both interfaces provide the same core torrent operations. Choose based on your workflow:

| Feature | CLI | GUI |
|---------|-----|-----|
| Create torrents | Yes | Yes |
| All create settings | Yes | Yes |
| Inspect metadata | Yes | Yes |
| Check integrity | Yes | Yes |
| Modify metadata | Yes | Yes |
| Batch operations | Yes | No |
| Preset support | Yes | Yes |
| Preset management | Manual YAML | Visual editor |
| Progress display | Text | Visual with progress bar |
| File tree view | Text | Interactive & searchable |
| Scripting/automation | Yes | No |
| Theme customization | No | Yes |
| Drag and drop | No | Yes |
